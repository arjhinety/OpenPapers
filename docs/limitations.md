# Known limitations

## What OpenPapers 1.0 guarantees — and what it does not

OpenPapers 1.0 is a provenance-first **infrastructure layer**: it reliably discovers works by identifier or exact title, retrieves and ingests them, extracts and reconciles evidence with source locators, and refuses to fabricate what it cannot support (fabricated-answer rate 0 on the frozen v5 holdout). It does **not** guarantee high-quality open-ended scholarly search: describing a paper from memory and expecting the system to find it is *fuzzy discovery*, which measures Recall@10 ≈ 0.50 in the recorded live evaluation. Fuzzy retrieval is a roadmap item, not part of the 1.0 quality contract.

- **Fuzzy discovery:** natural-language descriptions ("there was a paper about recovering reasoning ability in small models…") resolve in roughly half of recorded cases. Prefer a DOI or arXiv identifier for reliable discovery.
- **Exact-title retrieval:** title-only searches can miss or mis-rank a canonical work when upstream providers return incomplete or competing records. A provider-native DOI or arXiv identifier is the reliable fallback. Improving exact-title ranking and identifier probing is a deferred roadmap item in [architecture.md](architecture.md).
- **Provider availability:** anonymous APIs can return rate limits, transient failures, incomplete records, or different result ordering over time. Failures are retained in `transparency.providerFailures`.
- **PDF parsing:** Parsed documents retain parser provenance (`grobid`, `pymupdf`, or `docling`) and source page locators for structured elements. GROBID header fidelity is measured against the frozen `pdf-gold-v1` set (26 real arXiv papers): title token F1 0.976, author recall 0.774 / precision 0.825, abstract token F1 0.957. Measured fidelity covers header fields on arXiv-style papers; table, equation, and caption structure is not gold-scored, and non-arXiv layouts are unmeasured. Optional PyMuPDF and Docling fallbacks require local installation and are not enabled by default; the shipped PyMuPDF pipeline extracts text and sections but does not attempt title/author metadata.
- **Derived extraction:** heuristic facts, claims, parameters, and recipes are source-located but are not independent scholarly verification. Unknown values remain unreported.
- **Repository safety:** GitHub and Hugging Face content is inspected as data only. The system does not execute repository code, notebooks, model code, or downloaded scripts.
- **Retrieval terminology:** the SQLite/default backend is **not** semantic vector retrieval — it uses the bundled `lexical-hash-v1` deterministic token-hash retriever. Only PostgreSQL with a real embedding backend is a semantic/vector capability, and even there semantic quality is unbenchmarked: vector records retain `embeddingProvider` and `dimensions`, SQL search filters on both so unrelated embedding spaces are never compared, and equal dimensions do not imply semantic compatibility. A real embedding provider must be supplied through the `EmbeddingProvider` seam.
- **Response caching:** caching is deliberately conservative. Authorization, cookies, proxy credentials, credential-like query parameters, `Set-Cookie`, and identity-sensitive `Vary` responses bypass caching; this protects correctness but does not implement every HTTP cache directive.
- **Legacy arXiv identifiers:** the identity resolver accepts modern `NNNN.NNNNN` and supported pre-2007 category-style identifiers (`cond-mat/9703183`, `cs/9809110`), including revision and URL forms. Unknown categories and malformed identifiers are rejected and surfaced in `transparency.providerFailures`, never silently treated as missing records.
- **Fact candidate extraction:** candidate generation is intentionally high-recall and deterministic, while predicate-aware validation uses sentence locality, section/reference filtering, assertion status, and experimental role. It remains heuristic; tables, OCR artifacts, and unusual layouts can still produce ambiguous or rejected candidates. Rejected candidates retain raw evidence in development diagnostics.
- **License scope:** external papers, metadata, datasets, model weights, cards, and repositories are governed by their own licenses and terms.
